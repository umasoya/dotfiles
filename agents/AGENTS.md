# 共通の作業方針

- 日本語で簡潔に説明する。
- 作業対象のリポジトリにある指示と既存の規約を確認する。
- コミットメッセージはConventional Commitsに従い、`<type>[optional scope][!]: <description>`の形式にする。例: `feat(shell): 補完設定を追加`、`fix(deploy): リンク先の競合検出を修正`、`chore(nix): 不要なパッケージを削除`。破壊的変更には`!`または本文の`BREAKING CHANGE:`を使う。作業対象のリポジトリに別の明示的な規約がある場合はそちらを優先する。
- macOSとUbuntu on WSL2で共有する設定では、マシン固有の絶対パスを避ける。
- 変更に合った検証を行い、未検証の点を明記する。
- 認証情報、セッション履歴、仕事用の非公開情報をdotfilesに含めない。
